Orders are typed into Kram by hand at the moment. That is fine for showing the software and untenable for running a factory on it. To build the import we need one thing: a real export file out of Panipuri, exactly as Panipuri produces it.

Why we are asking now rather than later

This is the only outstanding item where the thing we need does not exist yet — it has to be produced, not found. Everything else on our list is a document someone already holds or figures someone already knows.

It is also on the critical path to going live. We would rather the request sat with you for a few weeks than arrive the day we are ready to build against it.

What would be most useful One file
  • Twenty to fifty orders is plenty. We are learning the shape of the file, not loading your order book.
  • Exactly as it comes out — its own column headings, its own date format, its own spellings. Please do not tidy it up: the mapping has to be written against what Panipuri actually produces, and a cleaned copy teaches us the wrong thing and hides the problems.
  • If possible, one order that ships in more than one container. Kram treats each shipment as its own deadline — 400 chairs in August and 600 in September are two separate plans from one order. A file with only single-shipment orders would hide the case the whole design is built around.
  • Excel, CSV, text — whatever it exports. Any of them is fine.

The question worth answering first

Does Panipuri hold a container stuffing date at all, or only a customer delivery date?

Everything Kram calculates hangs off the stuffing date. If Panipuri does not carry one, the import still works — orders, customers, quantities and articles all come across — but somebody in merchandising will need to add the stuffing date in Kram before an order can be planned.

That is a perfectly workable arrangement. It is just much better decided now, with you, than discovered by us halfway through building the import.

Two practical questions They decide how the import works
QuestionWhat it changes
Which report produces it? So we can ask for the same one again, and so the person running it every week knows exactly which button.
How often can it be run? Nightly, on demand, weekly. If it can be produced to a schedule the import can run by itself; if not, it becomes a file somebody uploads, which is also fine and worth knowing.

What we need back

One export file, untidied, and an answer on the stuffing date. Nothing else is blocking, and the file matters more than the answers — most of what we need to know, we can read out of it.
