Around a hundred and twenty comments in this codebase cite a specification by section — spec §4, spec §11, spec §16 — and several quote it directly. For ten weeks this note said there was no such file anywhere. There was: it is docs/specification-rev-b.html. This note now exists so that the next reader knows where it is, and why it was missed.

What happened 17 August, 28 August, 28 October 2026

A specification numbered DBBS/UM/KRAM/01 Rev B, dated 10 August 2026, was written up early in the project from U&M's concept deck and the conversations around it. On 17 August it was believed to have been drafted inside a working session and never saved — the project log had recorded it as “truncated at ~50k characters” and as something the client still owed, and both were wrong: the DBBS/ prefix is our own numbering, so it was always ours to hold.

It had been saved. On 28 August it was committed to the repository as docs/<!DOCTYPE html>.html — named by accident after its own first line, in a commit about interim figures — and nobody opened it. On 28 October it was read: twenty sections, Rev B, “for review”, product summary through phasing and the open-items table, with the section numbers the code cites. spec §11 is the scheduling engine and names roll_back_to_working_day; §6 is orders and schedule. It was renamed the same day.

What the deck is, and is not Checked, not assumed

docs/source/concept-deck.pptx is the client's brief and is genuinely the requirements document: nineteen slides covering objectives, dashboard features, a five-row scope of work, the MD's KPIs, and the screens they want. It is not the specification. It carries no speaker notes, embeds no documents, and contains no numbered sections at all — so no citation in this codebase resolves against it. They resolve against the specification.

Verified by reading the file rather than by opening it: nineteen slides, zero notes slides, zero embedded parts, zero section-style references anywhere in the XML.

If you need to know what a section said

Open docs/specification-rev-b.html and read the section. The citations mostly carry the sentence with them as well, so searching the codebase for the section number still returns the claim next to the code that implements it:

grep -rn "§11" --include=*.sql --include=*.ts .

Where the two disagree, that is a finding: the document predates the build, so it can audit the build — which a specification reconstructed from the code never could, and the reason one was deliberately not written in August.

Why it was missed

A file whose name begins with an angle bracket does not look like a document in a listing; it looks like an accident, and for two months it was read as one. The 17 August finding, repeated in three documents and the log's front table, was then believed over the directory it sat in. The lesson is the project's recurring one: a confident record is not evidence, and a stray file is worth opening before it is written off.
