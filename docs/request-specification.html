Kram is built against your specification DBBS/UM/KRAM/01 Rev B. The copy we are working from arrived cut short — it stops partway through section 19, and section 20 is missing altogether. We would rather ask for the whole document than keep building around the gap.

What we have, and where it stops Sections 1–20

Sections 1 to 18 are complete and have been used throughout. Nearly every decision in the software cites one of them — section 4 for scheduling at component level rather than whole chairs, section 6 for the shipment line being the unit everything is calculated from, section 11 for when the plan recomputes and how much it must handle, section 15 for using your ERP order number so that re-uploading a file corrects the orders rather than duplicating them.

The text ends partway through section 19, the phase plan. Section 20, “Open items”, is not there at all.

We did not save the partial copy into the project. A reference document that looks complete but is not is worse than none, because whoever reads it next has no way of knowing where it stops.

Why the missing section is the one that matters

Section 20 is where you listed what was still undecided when the specification was written. Every item on that list has since either been decided quietly by us while building, or is still open with neither side tracking it.

It is the only part of the document guaranteed to contain things we do not know that we do not know. Everything else we can check by reading; this we cannot.

What we are asking for Three things
  • The complete Rev B document as a file — PDF, Word or web page, whichever you hold it in. A file rather than pasted text, because pasted text is how it was truncated the first time.
  • Confirmation that Rev B is still current. It is dated 10 August and marked For review. If it has moved on since, we would rather build against the newer one.
  • Any of section 20 that has been settled in conversation since. Decisions taken in a meeting are just as good as decisions written down, as long as we know about them.

What we will do with it

The document goes into the project alongside the software, and every item in section 20 gets walked through one by one — each either closed with the decision that was actually taken, or written into our open items list as still owed. You get that list back.

It is also the one audit we have never been able to run. Your concept deck has been checked slide by slide against what is built. Your capacity model is checked automatically every time we run the tests. The specification, which is the document that actually governs the work, has never been checked end to end — because we have never had all of it.
